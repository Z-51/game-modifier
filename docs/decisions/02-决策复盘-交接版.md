## 1. 引言

### 交接目的

本项目是一个供编码 Agent 调用的单机游戏内存修改工具（CLI + MCP 双形态）。它的许多设计决定已经**外化为对调用方的承诺**：Agent 宿主（Claude Code / Codex CLI）的 prompt、恢复手册（AGENTS.md）、用户的脚本都在依赖这些行为。因此维护本项目的核心纪律是：

> **追加可以，破坏不行。** 大部分决策允许在其上生长新功能，但不允许改变既有行为、协议形状与字符串值。

### 阅读指引

- 第 2 节总表：30 秒定位某个决策的代码在哪、能不能动。
- 第 3 节硬性约束：动手改代码前必读，违反任何一条都可能破坏下游 Agent。
- 第 4 节决策详述：每个决策的落地位置、维护注意事项、守护测试。
- 第 5 节测试基线：怎么跑测试、基线数字、已知构建坑。
- 第 6 节开放决策：还没做的事，按优先级排好。

关键数字（截至本文实测，以 `scripts/refresh_metrics.py` 输出为准）：**858 个测试**（857 passed / 1 skipped，66 文件）、MCP 工具 **83 个 / 11 分组**、错误码 **40 个**、profile **5 档**、可选依赖 **8 组 extras**、反作弊签名 **16 种**。

## 3. 硬性约束清单（破坏性改动警告）

以下七条是项目的宪法级约束。任何 PR 触碰其中一条，默认应被拒绝，除非有明确的需求评审结论。

### 3.1 错误码值不可更改

`errors.py` 的 `ErrorCode` 枚举字符串值（如 `"E_NEEDS_SCAN"`）是 AI Agent 的分支条件（AGENTS.md 安全契约段逐条列出了 `error.code == X → 做 Y` 的恢复手册）。**只允许追加新枚举值，禁止改名、改值、删除或合并既有值**。新增前先查近义码（先例：UE 内省否决了新增 `E_UE_LAYOUT_INVALID`，复用 `E_LAYOUT_UNSUPPORTED`）。

### 3.2 JSON 信封结构不可更改

CLI 单行 JSON `{"ok": bool, "command": ..., "data"|"error": ...}` 与错误体 `{"code", "message", "hint?", "details?"}`（`output.py` Result / `mcp_server.py` `_envelope`）是外部协议。**只能向 data 内新增字段，不能改信封形状、不能删既有键**（先例：dry-run 只加 `impact` 字段，不删改现有键）。

### 3.3 MemoryBackend 禁止加 @abstractmethod

`memory/base.py` 的 `MemoryBackend` 是全部测试的承重墙：`tests/conftest.py` 的 `FakeBackend` 继承它，66 个测试文件依赖。**新增后端能力必须用"具体默认方法"实现**（先例：`read_many` 默认逐条 read，`windows.py` 覆写优化版）。加抽象方法会让 FakeBackend 实例化失败，全部测试崩。

### 3.4 readonly / default profile 行为冻结

`mcp_server.py` 的 `PROFILES`：default 与 readonly 的注册行为逐字冻结（`WRITE_TOOLS` / `READONLY_TOOLS` 集合是历史回归锚点，注释原文 "regression anchor"）。**新增 profile 档位可以（dry-run/symbols/limited 都是这么加的），修改既有两档的工具集合不行**。

### 3.5 dry-run 默认 + confirm 门控不可放宽

所有写操作（modify/nl/batch_run/save_edit_modify/template_apply/freeze）默认预览、显式 confirm 才执行，服务端二次校验。运行时 `dry_run_only` 档位由 `_gate_write` 前置拦截。**任何"便利化"改动（默认 confirm、跳过校验、客户端信任）都视为破坏安全契约**。只能收紧，不能放宽。

### 3.6 反作弊检测拒绝逻辑不可绕过

`safety/guard.py` 的 `detect_anti_cheat` 命中 16 种签名即 `E_ANTI_CHEAT` 拒绝附加。`find-writers` 等敏感工具对该场景直接拒绝。**禁止添加绕过开关、白名单、"仅读写不注入"之类的弱化路径**；签名表可扩充（纯数据追加，保持 `{detected, systems, hits}` 返回结构），但 VAC 类窄签名不要随手放宽或收紧（误报/漏报都是事故）。

### 3.7 追加式修改原则与测试基线门

- 所有计划文件共同的铁律："**新增独立子模块 + 服务层追加编排 + CLI/MCP 薄壳追加**"的最小变更策略。
- 测试基线门：`pytest --collect-only` 收集数 **858（截至本文实测），不可下降**，且全量必须通过。删除/跳过测试需要等量新覆盖 + 说明。
- 修复类改动遵循红绿反馈环：先写失败测试复现 bug（红），再修复（绿）。

## 4. 决策详述（落地位置与维护注意事项）

### 初始架构层（D1–D10）

#### D1. CLI + MCP 双模式设计
- **落地位置**：`service.py`（唯一业务层）；`cli.py`（argparse 薄壳，`main()` 入口）；`mcp_server.py`（FastMCP 薄壳，`main()` 入口）。入口点定义在 `pyproject.toml` `[project.scripts]`。
- **维护约束**：新功能先写 `service.py` 方法，再在两个壳各加一条 dispatch/注册；不要在壳里写业务逻辑。MCP 工具 docstring 是 Agent 的第一文档，写清使用时机。
- **相关测试**：`tests/test_cli.py`、`tests/test_cli_integration.py`、`tests/test_mcp_extended.py`。

#### D2. JSON 信封统一输出
- **落地位置**：`output.py` 的 `Result`（success/error + json/json-pretty/human 三种渲染）；`mcp_server.py` 的 `_envelope()`；输出限流 `_truncate_output()` / batch 专用 `_truncate_batch()`。
- **维护约束**：见硬性约束 3.2。`human` 模式只供人看，机器路径永远走 json。
- **相关测试**：`tests/test_output.py`、`tests/test_mcp_extended.py`（限流行为）。

#### D3. session 复用模型
- **落地位置**：`session.py`（`Session` dataclass + `SessionStore`，持久化在 `sessions/<id>/`）；`service.py` 的 `_load`/`_open` 生命周期骨架。
- **维护约束**：Session 新增字段一律 `field(default_factory=...)` + `from_dict()` 用 `.get()` 容错——**旧 session JSON 必须无需迁移即可加载**。session 文件只放小状态，大数据走 sidecar（见 D14/D22）。
- **相关测试**：`tests/test_session.py`。

#### D4. 稳定错误码体系
- **落地位置**：`errors.py`（`ErrorCode` 枚举 35 值 + 异常子类层级）。
- **维护约束**：见硬性约束 3.1。新增异常子类时同步考虑是否需要 `DEFAULT_HINT`（D27）。
- **相关测试**：`tests/test_errors.py`、`tests/test_error_hints.py`。

#### D5. dry-run 默认 + confirm 门控
- **落地位置**：`service.py` 各写方法的 `confirm: bool = False` 参数与预览分支；`safety/validation.py`（`validate_address` / `validate_write_span`）；`safety/guard.py`。
- **维护约束**：见硬性约束 3.5。新写操作必须复刻同样的门控骨架，包括 `_gate_write` 运行时档位检查（D24）。
- **相关测试**：`tests/test_safety.py`、`tests/test_safety_deep.py`、`tests/test_safety_extended.py`。

#### D6. 反作弊检测 = 拒绝附加
- **落地位置**：`safety/guard.py`（`ANTI_CHEAT_SIGNATURES` 16 系统签名表 + `detect_anti_cheat`）；`service.py` attach 路径调用；`errors.py` 的 `AntiCheatError`。
- **维护约束**：见硬性约束 3.6。扩充签名 = 纯数据追加；返回结构 `{detected, systems, hits}` 不可变（AGENTS.md 有消费方）。
- **相关测试**：`tests/test_safety.py`、`tests/test_safety_extended.py`（新签名命中/误报）。

#### D7. 写入前自动备份 + 审计
- **落地位置**：`safety/backup.py`（backup_create/list/restore）；`service.py` 写路径自动备份 + `audit.jsonl` 追加（`audit_tail` 工具读回）；save-edit 写 `.bak` 旁路备份。
- **维护约束**：审计记录格式 `{ts, op, args, result, backup_id}` 已有消费方，字段只增不改；确认写入必须同时产生备份与审计条目，两者缺一视为实现缺陷。
- **相关测试**：`tests/test_service.py`、`tests/test_mcp_extended.py`（audit 日志格式）。

#### D8. FakeBackend 测试架构
- **落地位置**：`memory/base.py`（`MemoryBackend` 契约）；`tests/conftest.py`（`FakeBackend` 字典式伪内存）。
- **维护约束**：见硬性约束 3.3。性能契约测试用 FakeBackend 读计数器断言系统调用次数（先例：UE 内省批读断言）。
- **相关测试**：`tests/conftest.py` 及其全部 66 个消费文件；`tests/test_windows_backend.py` 守护真实后端行为。

#### D9. 可选依赖组 + 懒加载降级
- **落地位置**：`pyproject.toml` `[project.optional-dependencies]`（radare2/frida/mcp/speed/disasm/crypto/dev/all 共 8 组）；各模块 try-import（scanner 的 numpy、`analysis/disasm.py` 的 capstone、`save_edit/unity.py` 的 pycryptodome、`mcp_server.py` 的 mcp）。
- **维护约束**：核心依赖只有 psutil/PyYAML/tomli，**不要把任何可选依赖提为核心**；缺失时抛 `E_DEPENDENCY_MISSING`/`E_TOOL_NOT_FOUND` 且必须带安装命令 hint；mcp 包缺失的测试用 `pytest.importorskip`。
- **相关测试**：`tests/test_disasm.py`、`tests/test_xrefs.py`、`tests/test_mcp_extended.py`。

#### D10. Windows 平台聚焦
- **落地位置**：`memory/windows.py`（ctypes 直调 kernel32）；`memory/process.py`（psutil 主路径 + Toolhelp 兜底）；非 Windows 抛 `E_UNSUPPORTED_OS`。
- **维护约束**：`windows.py` `read()` 的部分读取语义是修复过的行为（0 < read < size 视为失败，禁止回退为静默截断）；`read_many` 覆写按 VirtualQueryEx region 边界裁剪，区间绝不跨 region。
- **相关测试**：`tests/test_windows_backend.py`。

### 分析能力层（D11–D17）

#### D11. confidence + evidence 输出约定
- **落地位置**：`engines/detect.py`（引擎检测 `{engine, confidence, evidence}`）；`analysis/report.py`（布局分析统一输出）；`engines/ue_introspect/layout.py`（`{verdict, confidence, hypotheses}`）。

- **相关测试**：`tests/test_engines_deep.py`、`tests/test_layout.py`、`tests/test_ue_introspect.py`。

#### D12. UE 内省：可验证假设探测
- **落地位置**：`engines/ue_introspect/`（layout.py 探测 / fname.py 解码 / actors.py 枚举，三文件子包，勿再拆分或膨胀）；`[ue]` 配置段默认值走 `config.get("ue", key, default=...)`（**不改 config.py property**，保护 `tmp_config` fixture）。
- **维护约束**：探测判据（指针形状占比、SerialNumber 单调性、可打印比例）是置信度的来源，改判据必须同步更新测试布点；失败返回 `verdict=failed` + evidence，不抛异常；`engines/unreal.py` 保持离线 dumper 解析定位，勿混入在线探测。
- **相关测试**：`tests/test_ue_introspect.py`、`tests/test_ue_service.py`。

- **落地位置**：`engines/ue_introspect/actors.py` `_read_span_groups()`（排序→gap 归组→整段读→失败退化逐地址）；`memory/scanner.py` next_scan 的 region 归组批读（`use_batch_read` 可回退）。
- **维护约束**：**禁止在散列指针路径上使用 `read_many`**（per-address VirtualQueryEx 在大地址集下慢一个量级）；归组阈值取 `[ue] batch_gap` 配置；性能回归用读计数器断言拦截。
- **相关测试**：`tests/test_ue_introspect.py`（批读次数断言）、`tests/test_scanner_deep.py`（批量读与逐地址等价性）。

- **相关测试**：`tests/test_pointer_scan.py`、`tests/test_pointer_rescan.py`、`tests/test_scan_cache.py`、`tests/test_pointers_deep.py`。

### token 效率层（D18–D22）

#### D18. 临时符号 + name chain
- **落地位置**：`service.py` `name_chain`（注册 `name.step0..stepN` 中间态，默认 temp）/ `name_clear_temp`；`memory/pointers.py` 地址表达式求值；`value_convert` 工具。
- **维护约束**：temp 符号与持久符号的清理边界由 `name_clear_temp` 把守（只清 temp）；地址算术只支持 +/-，负结果拒绝——服务端求值原则不可回退为"让 Agent 手算"。

### 5.2 FakeBackend 用法速查

- 位于 `tests/conftest.py`：字典式伪内存，继承 `MemoryBackend`。
- 布点：直接写 `backend.mem[addr] = bytes`；指针网络用 `struct.pack("<Q", ...)` 助手写入。
- 性能断言：给 FakeBackend 加读计数器，断言批读次数是 O(chunks+groups) 而非 O(N)（UE 内省测试先例）。
- 超时测试：`monkeypatch time.monotonic`（`test_pointer_scan.py` 先例）。
- mcp 包缺失：`pytest.importorskip("mcp")`。
- **铁律：MemoryBackend 新增能力用具体默认方法，禁止 @abstractmethod。**

### 5.3 wheel 重建的陈旧 build 目录坑

已知事故：新增子包后 `python -m build --wheel` 使用了陈旧的 `build/` 目录，导致 wheel 遗漏新模块（安装后 `ModuleNotFoundError`）。**新增模块后重建 wheel 前，先删除 `build/` 与旧的 `dist/*.whl` 再构建**，并解包检查新模块确实在 wheel 内：

```powershell
Remove-Item -Recurse -Force build, dist ; python -m build --wheel
```
